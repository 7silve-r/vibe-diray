# Vibe Random Notes

一个可以边听音乐、边记录生活的随心记应用。音乐与日记共用账号，页面采用轻盈的天空背景和透明玻璃界面。

## 可以做什么

- **听音乐**：浏览歌曲、歌手和歌单，按歌曲名、歌手、专辑搜索，收藏喜欢的音乐，查看推荐与评论。
- **随手记录**：按分类管理日记，使用 Markdown 编辑，上传封面，自由选择私有或公开。
- **分享与互动**：游客可浏览公开日记；登录后可点赞、评论、收藏，管理自己的评论。
- **持续播放**：音乐和日记共享播放器。悬浮黑胶小窗支持拖动、展开、暂停和切歌，切换页面不会中断播放。
- **个人空间**：修改昵称、头像和密码；编辑中的草稿保存在当前浏览器。主页支持诗签和本机心情留笺。
- **内容管理**：管理员可维护歌曲、音频与封面、歌手、歌单、轮播图、用户与反馈，并删除公开日记及违规评论。

管理员不能查看他人的私有日记，也不能编辑他人的正文。刷新或关闭网页会结束当前播放；清理浏览器数据会删除本机草稿和留笺。

## 首次使用

### 1. 准备环境

本地一键启动脚本面向 **Windows**，需要：

| 软件 | 要求 |
| --- | --- |
| Java | JDK 17 或更新版本，`java` 可用 |
| Maven | 3.9 或更新版本，`mvn` 可用 |
| Node.js | 22 LTS 或更新的 LTS 版本，`node`、`npm` 可用 |
| MySQL | 8.0，已启动并可连接 |
| MinIO | 已启动，已创建音乐资源桶 |

首次安装依赖需要网络。MySQL 和 MinIO 作为独立服务运行，启动脚本检查它们的可用性，不安装服务、不重建数据库。

### 2. 初始化空数据库

仅对新项目的空数据库，依次执行：

1. [日记与账号表](backend/diary/sql/schema.sql)
2. [音乐表](backend/music/sql/schema.sql)

可以在 IDEA 数据库控制台或 MySQL 客户端中运行文件。两份脚本默认使用 `music_diary`；自定义库名时，须同时调整 SQL 中的库名和后续 `DB_URL`。**已有可用数据库不需要重复初始化。**

在 MinIO 中创建 `MINIO_BUCKET` 对应的桶。音乐音频、封面等公开资源需要允许匿名读取；不要允许匿名上传或删除。日记私有封面由后端检查权限后提供。

### 3. 填写本机配置

将根目录 [.env.example](.env.example) 复制为 `.env`，用编辑器填写：

| 配置 | 用途 |
| --- | --- |
| `DB_URL`、`DB_USER`、`DB_PASSWORD` | 共用 MySQL 数据库连接 |
| `JWT_SECRET` | 至少 32 字节的随机签名密钥，不要使用示例文本 |
| `ADMIN_PASSWORD` | 首次创建 `ADMIN` 账号的密码，8～64 个字符 |
| `APP_PORT` | 唯一后端端口，默认 `8081` |
| `WEB_PORT` | 前端端口，默认 `5173` |
| `UPLOAD_DIR` | 日记和头像存储目录，脚本将相对路径按项目根目录解析 |
| `UPLOAD_URL_PREFIX` | 上传访问路径，默认 `/uploads/`，以 `/` 开头和结尾 |
| `MINIO_ENDPOINT` | MinIO API 地址，例如 `http://127.0.0.1:9000`，不是控制台地址 |
| `MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET` | 音乐资源存储凭据和桶名 |
| `MAIL_*` | 可选 SMTP 邮件配置，暂不使用邮箱功能时保持未配置 |

每行写成 `名称=值`。值中的 `#`、`$`、`&`、`=` 按原文读取，也可以给整个值加一对引号；不要在值后面追加注释，不支持变量展开。根目录 `.env` 的配置优先于当前进程中同名环境变量，仅对本次启动及其子进程生效，不修改 Windows 全局环境变量。

`.env`、上传内容、日志和构建结果均不提交到 Git。配置模板中不能填写真实密码。前端的 `VITE_` 配置会公开给浏览器，不能用于保存密钥。

## 一键启动与停止

准备好数据库和 MinIO 后，双击根目录 **`start.cmd`**。脚本会：

1. 读取 `.env`，检查必填项、依赖服务和端口。
2. 构建并启动统一后端。
3. 首次运行时安装前端依赖，再启动前端。
4. 等待服务就绪，自动打开浏览器。

默认访问 **http://127.0.0.1:5173**。首次启动后，使用用户名 **`ADMIN`** 和配置的初始密码登录管理界面；普通用户可从右上角注册。修改 `.env` 中的管理员初始密码不会覆盖数据库里已有账号的密码。

双击 **`stop.cmd`** 停止脚本启动的前后端。它不会停止外部 MySQL、MinIO 或 IDEA 中的程序。重复启动会复用脚本已启动的进程；修改配置或代码后，请先停止再启动。

Git Bash 也可以在项目根目录使用：

```bash
./start.cmd
./stop.cmd
```

仅检查环境、不启动项目，或启动但不打开浏览器：

```bash
./start.cmd -Check
./start.cmd -NoBrowser
```

日志位于 `runtime/backend.out.log`、`runtime/backend.err.log` 和对应的 `frontend` 日志。启动中途失败会停止本次新启动的进程，保留日志供排查。

## 常见问题

- **缺少配置**：在根目录 `.env` 中填写提示的键名。不要把密码粘贴到公开问题或提交记录中。
- **MySQL 或 MinIO 无法连接**：先启动对应服务，并核对地址与端口。`-Check` 检查依赖连通性；数据库密码、表结构和资源权限仍需要服务实际启动、访问时验证。
- **端口占用**：先关闭之前由 IDEA、VSCode 或其他终端启动的同类服务，也可修改 `.env` 的 `APP_PORT`、`WEB_PORT`。脚本不会强行结束未知进程。
- **音乐图片或音频打不开**：确认 MinIO 桶允许读取、文件确实存在，且 `MINIO_ENDPOINT` 能被浏览器访问。
- **邮箱入口未显示**：默认关闭。配置后端 SMTP 后，在 `frontend/.env` 中设置 `VITE_MAIL_ENABLED=true`，重启前端。
- **IDEA 启动失败**：IDEA 直接运行不会自动读取根目录 `.env`。需在运行配置中设置对应环境变量，且不要与脚本同时启动后端。

## 开发与部署

IDEA 打开 `backend/pom.xml`；VSCode 打开 `frontend`。唯一后端启动类为 `com.silver.VibeApplication`。模块操作及测试命令见 [后端说明](backend/README.md) 和 [前端说明](frontend/README.md)。

一键脚本用于本机开发，前端使用 Vite 开发服务。正式部署请构建 `frontend/dist` 和 `backend/music/target/vibe-backend.jar`，配置 HTTPS 与同源反向代理；参考 [Nginx 示例](frontend/nginx.example.conf)。MinIO 的文件地址应对实际访问者可用。
